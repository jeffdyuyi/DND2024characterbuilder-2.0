# 数据处理核心原则 (Core Data Processing Principles)

本文件定义了在该项目中处理 D&D 原始文本数据时的核心逻辑与准则。所有开发与数据录入工作必须严格遵守以下原则：

## 1. 文本真实性与完整性原则

- **完全保留**：原始参考文档（如 TXT）中的所有文段必须得以完全保留。**严禁任何形式的杜撰、臆想或利用外部知识库来“填补”或“润色”文案**。
- **宁长勿短**：必须保留原始文档中的所有细节，严禁随意删减、合并或概括长文本。详尽的背景文字对于提升用户沉浸感至关重要。
- **原始存储**：在进行结构化提取之前，必须先将原始文本（包括引言、背景、特质详情）完整且无损地存储在数据对象的特定字段中。

## 2. 缺位留空原则

- **忠于来源**：如果参考文档中缺乏某项数据（如特定数值或描述），在 TS 代码中必须留空（如 `description: ''`）。
- **逻辑隔离**：代码的基础标准结构必须保持，缺失的内容通过前端渲染逻辑（如 `v-if`）处理，严禁为了“让数据好看”而编造参考文档中不存在的任何数据。

## 3. 严禁擅自变更数据

- **数据不可变性**：在未获得明确指令的情况下，**绝对不要**对 `src/data` 目录下已导入的数据进行增补、替换或缩略。
- **翻译准则**：中文名称、特质描述必须保持原样。除非收到明确的“更新”指令，否则禁止擅自修改任何现有翻译。
- **授权机制**：若发现参考文档与通用规则存在潜在冲突，必须优先向用户询问，严禁主观臆断。

## 4. 视觉微调规范

- **呈现优化**：允许在不改动任何字符的前提下，对长文本进行视觉排版调整（如 Markdown 的加粗、引用块、分段）。这些调整仅用于优化前端呈现，不得影响文本的真实表达。

## 5. 沟通优先准则

- **全中文汇报**：所有数据处理进度、核对情况及变更说明，必须使用中文回复。
- **严禁画蛇添足**：严禁执行任何未明确要求的操作，禁止擅自延展逻辑。遇到歧义必须优先确认。
