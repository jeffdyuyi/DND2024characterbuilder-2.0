# 角色卡精细化来源控制与规则适配：技术优化计划 (V2.0)

本计划旨在实现角色创建过程中的精细化来源控制（Source Filtering），确保玩家能够精确选择应用哪些官方、扩展及第三方合作书籍的规则与内容。同时，确保这些设定与现有的可选规则（Optional Rules）无缝融合，避免数据冗余。

## User Review Required

> [!IMPORTANT]
> **关于 HOMEBREW (家酿/自定义) 内容的严格界定**
> 
> 根据您的指示，本方案已在架构上将 `HOMEBREW` 明确独立出来。
> - `HOMEBREW` **绝对不会**用于指代《资源名称译名缩写对照.md》中列出的任何合作或第三方内容（如 Tal'Dorei (TCSR)、Grim Hollow (GH) 等）。
> - 那些合作内容将严格使用其专属的书籍缩写进行独立控制。
> - `HOMEBREW` 仅作为一个**占位符与独立开关**，专门保留给未来接入后端时，用于标记和控制“服务器上由玩家上传的纯原创内容”。

## Proposed Changes

### 1. 底层数据架构升级 (Data Models)

*   **定义全量强类型 Source 枚举**：
    从《资源名称译名缩写对照.md》中提取所有缩写，构建 TypeScript 联合类型 `DndSource`。
    ```typescript
    // 基于基石文档的精准映射
    export type OfficialSource = 
      | 'PHB' | 'DMG' | 'MM' // 2014 核心
      | 'PHB24' | 'DMG24' | 'MM24' // 2024 核心 (预留假定缩写)
      | 'SCAG' | 'XGE' | 'TCE' | 'FTD' | 'MPMM' | 'BMT' // 扩展书籍
      | 'TCSR' | 'GH' | 'VSS' | 'CBT'; // 合作与第三方 (完全独立开关)
      // ... 包含文档中所有项
      
    // HOMEBREW 作为完全独立的概念
    export type ContentSource = OfficialSource | 'HOMEBREW'; 
    ```

*   **扩展 CharacterState (角色状态)**：
    在角色数据结构中增加 `preferences` 字段，存储精细化的开关状态。
    ```typescript
    preferences: {
      allowedSources: Record<ContentSource, boolean>; // 精细到每一本书籍的开关
      optionalRules: {
        encumbrance: 'none' | 'standard' | 'variant'; // 负重规则
        hpType: 'fixed' | 'manual';                   // 生命值增长模式
      }
    }
    ```

### 2. 构建器首页 (Builder Step 0) 重塑

*   **新增“战役设定与来源偏好”步骤**：
    在玩家进入具体的种族、职业选择前，首先进入偏好设置面板。
*   **分组矩阵式 UI**：
    由于书籍缩写众多，UI 将根据《资源名称译名缩写对照.md》的分类进行分组呈现（核心、扩展&资源、合作内容等）。
    玩家不仅能一键开启/关闭某大类，更能**精细化点选**每一本特定的书籍（例如：只开启 PHB24 和 Grim Hollow (GH)，关闭其他一切）。
*   **HOMEBREW 独立区块**：
    在面板底部设立单独的“用户自创内容 (Homebrew)”开关，并附带提示：“允许加载未来通过服务器上传的玩家原创数据”。

### 3. 数据层过滤引擎注入 (Data Filtering)

*   **统一的解析器包装 (Source Resolver Wrapper)**：
    目前获取数据的函数（如 `allClasses()`, `allSpecies()`, `getFeats()`）将进行重构，接收 `preferences.allowedSources` 作为参数。
*   **底层映射规范**：
    严格检查所有现有 JSON 和 TS 数据文件，确保其 `source` 字段填写的完全是《资源名称译名缩写对照.md》中的缩写。如果存在混用或缺失，将进行数据清洗。
    *过滤逻辑示例*：如果某法术的 `source` 为 `TCSR`，但玩家偏好中 `allowedSources['TCSR'] === false`，则该法术将不会出现在法术选择列表中。

### 4. 可选规则 (Optional Rules) 适配逻辑

为了不产生数据冗余，可选规则的设置将直接以参数形式注入到现有的计算管线中：

*   **负重系统 (Encumbrance)**：
    无需在角色数据中保存计算后的负重状态。直接修改 `InventoryTab` 中的计算逻辑，读取 `preferences.optionalRules.encumbrance`。如果是 `variant`，则触发移动力减半等 UI 提示逻辑；如果是 `none`，则隐藏负重条。
*   **生命值计算 (HP Type)**：
    仅保留一个配置项 `hpType`。当配置为 `fixed` 时，升级时的 HP 直接按取半+1计算；为 `manual` 时，UI 显示输入框允许玩家手动输入掷骰结果。现有的 `character.combat.hp` 数据结构无需改变。

## 潜在风险与防范

1.  **数据回溯保护 (Retroactive Protection)**：
    如果玩家在角色已经拥有 `GH` 书籍中的专长后，在设置中关闭了 `GH`，会导致该专长渲染报错或丢失。
    *防范机制*：在关闭某个 Source 前，遍历角色当前已选的种族、职业、法术、专长。如果发现依赖，则禁止关闭并提示“您的角色当前包含依赖此书籍的内容，请先移除后再关闭”。
2.  **数据源字段标准化**：
    当前代码库中可能存在不符合《资源名称译名缩写对照.md》规范的旧有 `source` 标记。
    *防范机制*：在实施此系统前，我们将编写一个校验脚本或手动核查现有核心数据，确保所有 `source` 标签的纯净度和映射正确性。
