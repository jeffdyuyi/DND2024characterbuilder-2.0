# 页面视觉收敛与排版优化指南

## 目标与边界

本指南用于后续优化项目页面的视觉呈现：让界面更聚拢、字号层级更清晰、排版更统一，同时保持当前已经简洁的页面层级与主要操作路径。

本轮建议只调整样式、布局密度、视觉层级和响应式呈现，不改页面信息架构、业务规则、交互流程或内容语料。5etools-cn 等来源的译名、正文、风味文本及出版物元数据保持原样；视觉精简不能通过删文案或截断资料实现。页面结构如确有必要调整，应另行提出并审核，不混入视觉收敛工作。

## 现状观察

对全局样式与物种、职业页面样式文件的源码审阅显示，项目已经具备深色/浅色主题、颜色与间距变量以及统一容器等基础，但页面间仍存在排版尺度和视觉语言不一致的迹象：

- 全局正文字号为 16px，标题默认使用衬线字体；个别详情页标题达到 36px，副标题达到 20px，长描述与短标签目前缺少更细的层级区分。
- 全局间距变量与组件自身的 24px、40px、48px 等留白并存，页面的密度和节奏不完全一致。
- 全局容器最大宽度为 980px，但详情页又有较大的内部左右留白；主从布局中也有固定宽度侧栏。
- 部分职业样式存在未接入主题变量的浅色硬编码，与深色主题的基础配色不一致。
- 全局标题字体、局部字号、卡片内边距及边框处理尚未形成一套可复用的视觉规则。

以上是源码层面的观察，不代表已经完成所有页面的浏览器视觉验收。实施时应在真实页面中对照截图检查，尤其核对主题切换和窄屏布局。

## 视觉方向

建议采用“紧凑、清楚、克制”的方向：保留现有暗色奇幻主题和金色强调色，将装饰感集中在少数关键位置；通过稳定的字级、对齐和间距表达信息层级，避免每个标题、卡片都使用强边框、发光或渐变。

优先保持各页面当前的区块顺序、导航和主从关系。减少的是不必要的空白与重复强调，不是规则资料本身。完整规则正文应保持可读；密集列表可收紧行距和卡片间距，但不以小字号换取信息塞满。

## 建议设计基线

下列数值是供实施阶段试用和截图评估的候选值，不应未经页面验证就全局替换。优先将其整理为 CSS 变量，再逐页迁移。

### 字体与字级

| 用途 | 建议范围 | 使用说明 |
| --- | ---: | --- |
| 页面主标题 | 24–28px | 每页一个主要标题；避免大面积使用 36px 以上标题 |
| 区块标题 | 16–18px | 用字重、间距和颜色区分层级，不依赖夸张字号 |
| 卡片/条目标题 | 14–16px | 与正文保持明确但克制的差异 |
| 正文与规则描述 | 14–15px | 长文本默认不低于 14px；行高约 1.55–1.7 |
| 辅助说明 | 12–13px | 用于次级信息，需保持足够对比度 |
| 短标签/元信息 | 11–12px | 仅用于短内容；避免将长说明压缩为小字 |

将无衬线字体作为界面正文、表单、按钮和数据的默认字体；衬线字体可保留给页面主标题或少数有明确品牌作用的标题。控制字距，避免正文普遍增加字间距。字体加载失败时应有本地系统字体回退，不让布局依赖外部字体成功加载。

### 间距与密度

建议以 4px 为基础，逐步收敛为 `4 / 8 / 12 / 16 / 20 / 24 / 32` 的主要间距级别。页面区块之间使用 24–32px，卡片之间使用 12–16px，卡片内部使用 12–20px；同一类组件保持一致。40px 以上留白只用于页面级分段或明确的视觉停顿。

对于已有 40–60px 内边距的详情容器，可先尝试桌面端 24–32px，并在窄屏降到 16px。不要一次性压缩全站间距；先从视觉最松散、重复卡片最多的页面开始，确保内容呼吸感仍然足够。

### 页面宽度与对齐

建立可复用的页面宽度策略，而不是让每页各自叠加容器宽度和大内边距。当前 980px 容器可作为窄阅读页基线；多栏工作台可评估 1120–1280px 的桌面最大宽度，并根据实际导航与详情区比例验证。以上限值需由页面截图确认，避免宽屏上文本行过长。

主从列表页面可评估将固定侧栏从约 320px 调整到 260–280px，详情区使用剩余空间；仅在列表内容不发生难以区分的换行时采用。桌面端统一标题、正文和卡片的左边缘；窄屏时侧栏按现有交互方式折叠或移至内容上方，不新增复杂页面层级。

### 卡片、分隔与强调

- 使用背景明度、细边框和留白来区分卡片层次；同一页面避免同时混用多套圆角、阴影和边框粗细。
- 卡片圆角优先沿用现有 6/10/14px 体系，并按组件角色固定选值。
- 金色用于主要操作、选中状态或少量关键标记；正文链接、状态提示和普通边界仍应有独立且清晰的颜色语义。
- 渐变、发光和重阴影只保留在少数有明确层级意义的区域。普通卡片不需要都拥有装饰性效果。
- 长页面优先用稳定的区块间距或低对比度分隔线组织内容，避免每个条目都套一张厚重卡片。

### 主题与可读性

所有页面颜色应使用共享主题变量，不在组件中直接写入仅适用于浅色或深色主题的固定颜色。检查深浅主题下正文、辅助文字、边框、禁用状态和焦点状态的对比度；强调色不能只靠颜色变化传达状态。键盘焦点需清晰可见，交互目标和窄屏点击区域应保持易操作。

## 完整优化实施路线

以下步骤构成从现状盘点到全站验收的完整视觉优化路线。每一步都是独立审核点；完成后整理改动和截图证据，等待审核，再开始下一步。若某一步发现必须变更页面信息层级或操作流程才能解决的问题，先记录并单独评审，不在视觉实施中自行改动。

### 步骤 0：建立页面与组件清单

**目标：**明确要覆盖的页面和复用组件，避免只优化首页或单一主题。

**工作：**从路由及导航盘点实际存在的页面，按页面形态分类：角色库/首页、创建流程、角色卡及其分页、目录列表与详情、表单/选择器、弹窗/抽屉、设置与空状态。记录每页是否有深浅主题、桌面/窄屏形态、固定或滚动区域，以及其共享的导航、卡片和表单组件。页面名以仓库实际路由为准，不凭文档设想增加不存在的功能页。

**交付与验收：**页面矩阵、共享组件清单和优先级排序；主要入口及完整内容区域均被覆盖。未盘点前不改样式。

### 步骤 1：基线截图和问题记录

**目标：**建立可比较的优化前证据。

**工作：**从清单中选择高频主页面、列表详情页、数据密集页和长文本页作为代表样本。记录常用桌面宽度、窄屏宽度、深色与浅色主题截图；有关键交互状态的同时记录默认、悬停/聚焦、选中、禁用及展开状态。每张图记录路由、视口、主题和复现步骤。逐页列出至多三个最明显的视觉问题并标注严重度。

**交付与验收：**可复现的基线截图与问题列表。对比用数据和角色存档必须是测试数据；不得清空或覆盖用户存档。

### 步骤 2：确认视觉规则和候选 Token

**目标：**在全局改样式前确定可复用的设计约束。

**工作：**基于本指南候选值核对现有 `globals.css`、Tailwind 配置和局部模块样式，确定正文字级、标题层级、行高、间距、容器宽度、圆角、边框、阴影、颜色及断点的命名和用途。检查现有深浅主题变量及组件硬编码，形成“现有值—拟定值—影响范围”清单。颜色沿用现有主题语义，只有经对比验证后才调整颜色值。

**交付与验收：**经确认的 Token 表和迁移影响清单；不在此步大面积改页面。

### 步骤 3：整理全局设计变量与字体回退

**目标：**让后续组件具备统一、可维护的样式来源。

**工作：**将确认后的字级、行高、间距、宽度、圆角、边框、阴影和主题颜色收敛到全局变量或现有 Tailwind 主题配置。规范正文、界面控件及标题字体职责，补足合理的系统字体回退；检查字体加载失败时是否仍能正常排版。删除重复或未使用的视觉变量前先确认没有页面依赖。

**验收：**深浅主题均可读取正确变量；本步不造成页面结构或业务逻辑变化，且代表样本没有明显回归。记录受影响文件。

### 步骤 4：统一全局文字层级

**目标：**先统一可读性基础，再调整空间密度。

**工作：**按主标题、区块标题、条目标题、正文、辅助说明和短标签建立样式映射；逐类迁移全局基础元素及高频文本组件。区分数字/属性数值与长规则文字；避免全站统一套用装饰衬线标题。长规则文本保持完整，阅读字号原则上不低于 14px；仅短标签和元信息可使用更小字号。

**验收：**代表样本层级清晰，长文本行高舒适、换行正常，表单标签与提示可读；没有依赖缩小所有字号制造密度的结果。

### 步骤 5：收敛导航和页面框架

**目标：**先稳定全站对齐和页面可用宽度。

**工作：**调整应用级导航、页面容器、标题区、内容区和底部区域的宽度、左右边距及垂直节奏。将阅读型单栏与工作台/主从型页面分别处理，避免为统一而强行使用相同最大宽度。按现有导航关系组织，不新增、合并或重命名导航层级。

**验收：**代表页面标题、正文和主要操作的对齐关系稳定；桌面没有不必要的大块空白，窄屏没有横向滚动或导航遮挡。

### 步骤 6：统一高频基础组件

**目标：**收敛用户反复接触的交互元素。

**工作顺序：**按钮与链接 → 输入框/下拉/复选与单选 → 标签与状态提示 → 卡片和列表行 → 分隔线与提示块。统一高度、内边距、圆角、边框、字级、状态反馈和键盘焦点样式。优先复用项目既有组件及样式机制；只有多个真实页面存在共同需求时才抽取共享样式，不为视觉统一而大规模重写组件架构。

**验收：**同类组件在深浅主题下外观一致，默认/悬停/聚焦/禁用/错误/选中状态可区分；交互行为不变。

### 步骤 7：完成角色库/首页视觉收敛

**目标：**优化项目主要入口的密度与浏览效率。

**工作：**依照当前页面结构处理页面标题、搜索筛选区域、角色/项目条目、空状态和主要创建入口。优先减少重复卡片间距和过大的内部留白；列表内容、筛选能力、排序方式和操作入口保持原样。桌面列数依据最小可读卡片宽度调整，窄屏使用现有单列或既有响应式行为，不强制加入新的悬浮按钮或控制区。

**验收：**从基线截图对照，首屏信息分布更均衡；卡片标题、摘要和操作无截断，搜索与创建入口仍容易找到。

### 步骤 8：完成创建器与角色卡视觉收敛

**目标：**提高数据密集页面的扫读能力，并保持角色操作顺手。

**工作：**分别检查属性/技能、战斗数值、职业种族特性、装备、法术及其他实际存在的区域。规范数值、标签、规则说明和编辑控件间的关系；对已有分栏仅调整比例、间距和断点，不把页面强行重构为新仪表板，也不改变现有分页或操作步骤。核对长特性描述、输入错误和未填写状态。

**验收：**数值可快速定位，完整特性正文可读；编辑、保存、切换分页与既有快捷操作仍按原流程工作。用测试角色验证，不触碰真实角色数据。

### 步骤 9：完成目录、详情、表单与覆盖层

**目标：**让非首页页面也符合同一套视觉规则。

**工作：**按步骤 0 中的真实页面清单逐类迁移目录列表、详情内容、选择流程、设置、弹窗、抽屉和提示状态。对主从布局只优化侧栏宽度、内容间距和折叠呈现；完整保留规则文本、来源信息、过滤项和手动选择项。检查弹窗在窄屏内可滚动且关闭/确认操作不被遮挡。

**验收：**同一类别的页面布局一致；筛选、选择、关闭、确认和返回流程未改变；来源内容完整。

### 步骤 10：主题一致性和可访问性修正

**目标：**修复样式变量迁移后的对比度和操作识别问题。

**工作：**扫描页面级颜色硬编码，判断是否应替换为主题变量；区分错误、警告、成功、信息和选中状态。分别检查深浅主题的文本与边界对比、键盘焦点、键盘操作、控件标签、缩放下布局及状态提示。不能只靠颜色传递状态；避免闪烁或持续动画成为唯一反馈。

**验收：**主题切换无明显断层；焦点可见，状态可辨，常用缩放下内容不重叠。发现对比度问题时记录具体页面和控件后修复。

### 步骤 11：完成响应式断点与溢出治理

**目标：**验证页面在实际可用宽度下稳定呈现。

**工作：**先沿用项目既有断点；仅在真实布局失效时新增断点。检查桌面、平板/窄窗口、手机窄屏下的容器、分栏、导航、表格/列表、长标题、弹层和固定操作区。优先让现有内容自然重排或横向滚动局部控件，不隐藏重要字段、不截断规则正文，也不增加信息架构层级。

**验收：**代表及边界宽度下无页面级横向溢出、遮挡或不可达操作；局部确需滚动的区域有清楚边界和可用操作。

### 步骤 12：全站视觉回归、收尾与规范固化

**目标：**确认改动完整、可追溯并能供后续维护。

**工作：**沿步骤 0 的页面矩阵逐项复核路由、视口和主题；对照基线截图检查密度、对齐和文字层级。核验导航与内容顺序、原始数据/文案、关键操作、规则计算与角色存档行为未因样式调整受影响。删除本次迁移明确废弃的样式规则前，确认无引用。将最终 Token、组件约束、已知页面例外和未完成项更新到本文。

**交付与验收：**完成/未完成页面矩阵、前后截图、改动摘要、发现的问题及限制；所有未通过项有明确记录，不以“整体看起来正常”代替逐页证据。

## 每一步的审核记录模板

每个实施步骤完成后，填写并提交以下记录，用户审核通过后才进入下一步：

- **步骤与范围：**本次阶段编号、页面/组件、涉及文件。
- **实际改动：**发生了什么视觉变化，是否触及共享样式。
- **客观证据：**前后截图的路由、视口、主题；必要的构建或页面运行结果。
- **现存限制：**未覆盖页面、未通过状态、字体/环境限制或待定设计选择。
- **下一步建议：**按本路线顺序指出下一阶段，不跨步扩展范围。

## 验收清单

- 页面主标题、区块标题、正文、辅助文字具有稳定层级；没有为了“紧凑”把长文本缩到难读。
- 同类页面的容器宽度、左右边距、区块间距和卡片内边距一致；不同页面类型的差别有明确理由。
- 页面没有重复的大块空白，也没有卡片、文字和操作挤在一起的情况。
- 深色和浅色主题下文字、边界、交互状态均可辨认，没有单主题硬编码造成的突兀区域。
- 桌面和窄屏没有横向溢出、遮挡、异常换行或固定侧栏挤压主内容的问题。
- 导航、区块顺序、主要操作路径保持原状；视觉优化没有擅自改写、删减或截断任何规则与来源内容。
- 代表性页面截图经人工对照后，视觉密度有改善且规则长文本仍然容易阅读。

## 建议的第一步

按完整路线先完成步骤 0 和步骤 1：盘点真实页面与共享组件，随后记录代表性页面的桌面/窄屏及深浅主题截图。截图基线和清单审核通过后，再开始设计变量迁移。

## 优化落地与固化记录 (已实施)

### 1. 全局设计 Token 固化 (`src/app/globals.css`)
- **4px 间距阶梯**：`--space-3xs: 2px`, `--space-2xs: 4px`, `--space-xs: 4px`, `--space-sm: 8px`, `--space-12: 12px`, `--space-md: 16px`, `--space-20: 20px`, `--space-lg: 24px`, `--space-32: 32px`, `--space-xl: 40px`, `--space-2xl: 64px`。
- **字级层级基准**：
  - 页面主标题：`--font-size-page-title: 26px`（h1）
