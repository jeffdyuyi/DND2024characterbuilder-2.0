# 角色创建流程与卡面生成设计方案

> **版本**：v2.0 (2026-09)  
> **定位**：角色创建向导（Builder）、规则引擎驱动、三层状态解耦及可编辑卡面渲染的核心技术方案。合并并替代原 5 篇建卡与代码优化过程文档。

---

## 一、系统全链路架构模型

项目采用“**在线数据源 + 运行时适配器 + 机制覆盖层 + 纯函数计算引擎 + 编辑态卡面**”的解耦架构：

```text
[5etools 镜像库 (CN 2.0)]
       │ (HTTP / fetchJson / IndexedDB Cache)
       ▼
[Catalog 统一适配层 (src/lib/5etools/)] ─── 过滤: 来源/版本 (2014 vs 2024)
       │ (归一化为 CatalogEntry)
       ▼
[Mechanics Overlay 机制覆盖层 (src/mechanics-overlay/)] ─── 补充机器可计算特性
       │ (mergeWithOverlay)
       ▼
[Builder 9 步向导 (UI 状态机)] ─── 维护持久化 CharacterState (原始选择与覆写)
       │
       ▼
[规则计算引擎 (src/engine/)] ─── 纯函数计算 (ability, combat, spellcasting)
       │
       ▼
[最终角色卡适配器 (viewAdapter.ts)] ─── Computed + Overrides = Final View
       │
       ▼
[可编辑交互式角色卡面 (src/app/sheet/[id]/)]
```

## 二、角色创建 9 步流程状态机

角色创建向导分为 9 个步骤，步骤间严格区分“前置依赖”与“状态隔离”：

| 步骤 | 路由路径 | 核心业务与规则约束 | 依赖数据 |
|---|---|---|---|
| **Step 1: 基础设定** | `/builder/meta` | 设定角色名、玩家名、战役、规则版本（2024/2014）、允许的书源过滤池。 | 系统配置 |
| **Step 2: 种族与血统** | `/builder/species` | 选择种族与亚种/血统。2014版包含固有属性加值；2024版仅提供体型、速度、感官及固有特性。 | 5etools 种族库 + Overlay |
| **Step 3: 职业与兼职** | `/builder/class` | 选择初始职业、生命掷骰方式（固定值/骰点）、起始豁免与技能熟练、子职业（达到等级要求时）。 | 5etools 职业库 + Overlay |
| **Step 4: 背景与起源** | `/builder/background` | 2024 规则下绑定属性加值（+2/+1 或 +1/+1/+1）、起源专长及工具熟练；2014 规则下提供背景特性与技能。**保留手动自定义开关**。 | 5etools 背景库 |
| **Step 5: 属性分配** | `/builder/abilities` | 支持标准阵列 (15,14,13,12,10,8)、购点法 (27点)、手动掷骰。结合种族/背景加值自动计算调整值。 | Step 2 & 4 加值结果 |
| **Step 6: 起始装备** | `/builder/equipment` | 支持职业 A/B 套装选择或纯金币自购。支持武器属性与 2024 武器掌握 (Weapon Mastery) 标记。 | 5etools 装备库 |
| **Step 7: 法术配置** | `/builder/spells` | 若职业具备施法特性，根据主属性与等级筛选法术池。配置戏法、已知法术与准备法术。 | 5etools 法术库 |
| **Step 8: 专长与恩惠** | `/builder/feats` | 等级 4+ 属性提升/专长选择；传奇等级史诗恩惠。检查前置条件与属性依赖。 | 5etools 专长库 |
| **Step 9: 检阅与生成** | `/builder/review` | 全局属性校验、缺失项警告、确认并生成完整角色卡，跳转至可编辑卡面。 | 规则计算引擎全量校验 |

## 三、数据模型设计 (CharacterState V2)

### 3.1 核心状态分层

为避免表单扁平化污染与视图混杂，角色状态严格划分为三大领域：

```ts
interface CharacterState {
  id: string;
  version: 2; // Schema 版本号
  
  // 1. 元数据与规则环境
  meta: {
    name: string;
    playerName: string;
    ruleVersion: '2024' | '2014';
    enabledSources: string[]; // 如 ['XPHB', 'XDMG']
    avatarUrl?: string;
  };

  // 2. 原始选择记录 (Source & User Selections)
  origin: {
    speciesId?: string;
    subspeciesId?: string;
    backgroundId?: string;
    backgroundAbilityBonuses?: { ability: string; bonus: number }[];
    selectedLanguages: string[];
    selectedTools: string[];
  };

  progression: {
    classes: {
      classId: string;
      level: number;
      subclassId?: string;
      hpRolls?: number[];
    }[];
  };

  abilities: {
    generationMethod: 'standard' | 'pointbuy' | 'rolling' | 'manual';
    base: Record<'str' | 'dex' | 'con' | 'int' | 'wis' | 'cha', number>;
  };

  inventory: {
    items: {
      itemId: string;
      quantity: number;
      equipped: boolean;
      attuned: boolean;
      customNotes?: string;
    }[];
    currency: { cp: number; sp: number; ep: number; gp: number; pp: number };
  };

  spells: {
    cantrips: string[];
    knownOrPrepared: string[];
    overrideSlots?: Record<number, number>;
  };

  feats: {
    featId: string;
    chosenAbility?: string;
  }[];

  // 3. 手动覆盖层 (Manual Overrides)
  manualOverrides: {
    abilityScores?: Partial<Record<string, number>>;
    armorClass?: number;
    maxHp?: number;
    speed?: number;
    initiativeBonus?: number;
    proficiencyBonus?: number;
    spellSlotsMax?: Record<number, number>;
    attunementLimit?: number;
  };
}
```

## 四、规则计算引擎与角色卡渲染管线

1. **纯函数计算 (Computed)**：
   - `src/engine/ability.ts`：合并 `base + origin + feats` 计算属性总值与修正。
   - `src/engine/combat.ts`：计算基础 AC（结合护甲与体质/感知无甲加值）、最大生命值、先攻、熟练加值。
   - `src/engine/spellcasting.ts`：计算法术攻击命中、法术豁免 DC、可用法术槽位表。

2. **视图适配器合并 (viewAdapter.ts)**：
   - 提取 Computed 计算结果；
   - 检查 `manualOverrides` 对应键位；
   - 若存在手动值，优先使用手动值，并标记 `isOverridden: true`，记录原始计算值与偏离度。

3. **双端响应式卡面渲染 (Sheet UI)**：
   - 桌面端：仿既白卡面的高信息密度三栏布局；
   - 移动端：折叠抽屉 + 顶部状态卡底部的 Tab 切换布局；
   - 所有被手动覆盖的数值呈现 `✎` 编辑标记，提供 `↺` 一键还原按钮，保障用户自由度与规则严谨性的统一。
